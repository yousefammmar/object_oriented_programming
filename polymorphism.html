Summary

01 · What is polymorphism?

  • "Many forms": the same call behaves differently depending on the actual object type.
  • You write general code with base-class pointers or references that works for every derived class.
  • A base pointer can point to a derived object — Shape* s = new Circle(); — but not the other way round.

02 · Static vs dynamic binding

  • Without virtual, s->draw() follows the pointer type and prints "Drawing a shape" — static binding, decided at compile time.
  • With virtual void draw() in the base and void draw() override in the derived class, the real object decides at runtime — dynamic (late) binding.
  • Calling through an object name (c.draw();) is always compile-time; only pointers and references are polymorphic.

03 · The four rules

  • Polymorphism needs: inheritance, a base-class pointer or reference, the function declared virtual, and the function overridden in the derived class.
  • override is optional but recommended — the compiler then catches mismatched signatures.

04 · Abstract classes

  • A pure virtual function has no body in the base: virtual void draw() = 0;
  • A class with at least one is abstract — Shape s; is not allowed, but Shape* and Shape& are.
  • A derived class becomes concrete only once it implements every pure virtual function.

05 · Virtual destructors

  • Without one, deleting through a base pointer runs only the base destructor — a memory leak.
  • Declare virtual ~Shape() = default; so the derived destructor runs first, then the base.

06 · Arrays of base pointers

  • Shape* shapes[3]; can hold a Circle, a Rectangle and a Triangle; shapes[i]->draw(); calls each one's own version.
  • Free them with delete shapes[i]; in a loop — this is why the destructor must be virtual.
  • This replaces error-prone switch statements on type: each class handles its own behaviour, so adding a shape is easy.

Extra Notes · beyond the PDF

Good to know

  • virtual is only needed in the base class — overrides stay virtual automatically (still write override).
  • Polymorphism only works through pointers or references. Copying a derived object into a base object slices off the derived part (object slicing).
  • An abstract class can still have data members, constructors and normal functions.

Common mistakes

  • Forgetting virtual in the base — calls go to the base version (static binding).
  • A different signature (a missing const, another parameter type) makes a new function instead of an override — override catches it.
  • No virtual destructor in a base class used through pointers — the derived destructor never runs.
  • Trying to create an object of an abstract class.

Exam tip: which function runs?

  • Is the call through a pointer or reference, and is the function virtual? If both, the real object's type decides.
  • Otherwise the declared type of the pointer or variable decides.
