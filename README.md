## Topics Covered
 
### 01 · C++ Basics
Functions, loops, arrays, pointers, references, dynamic memory (`new`/`delete`), strings.
 
**Key concepts:** Variables & data types · For/while/do-while · 1D & 2D arrays · Pointers & references · Dynamic memory
 
### 02 · Class Basics
Class definition, access modifiers, setters/getters, constructors, destructors, copy constructor, `.h`/`.cpp` file separation, arrays of objects.
 
**Key concepts:** `public`/`private` access · Default & parameterised constructors · Initialiser list syntax · Copy constructor · Destructor · Header-source separation
 
### 03 · Const & Static
Constant member variables, constant member functions, static member variables, static member functions.
 
**Key concepts:** `const` after parameter list · Must init `const` in initialiser list · `static` defined outside class · `ClassName::method()` call syntax
 
### 04 · Composition
The has-a relationship — objects as members of other objects. Member object constructor ordering.
 
**Key concepts:** Class containing objects of other classes · Member object constructor runs first · Initialiser list construction · Example: `Person` has-a `Date`
 
### 05 · Labs & Practical Work
Ten labs progressing from C++ revision through pointers, classes, constructors, const/static, composition, operator overloading, inheritance, and polymorphism.

## Project Documentation (for developers)

The site is **plain HTML + CSS + vanilla JavaScript** — no framework, no build step — so it deploys to GitHub Pages as-is. It is split into one HTML file per section and small, single-purpose CSS/JS modules. Every file starts with a header comment explaining its purpose, and every function has a doc comment.

### How a page is put together

Each page file contains only its **own content** inside `<main id="main">`, plus `<link>` tags for the five stylesheets and `<script>` tags for the modules. When the scripts run, `layout.js` builds the shared shell (sidebar, top bar, masthead, footer) from `config.js` and moves `<main>` into it. This keeps navigation defined **once** instead of copied into nine files.

Script order (each page): `config → storage → theme → layout → progress → library → search → page-features → [code-data → code-viewer on code-files.html] → app`. `app.js` runs last and calls each module's `init()` in the right order.

### Module reference

| File | Main functions |
|---|---|
| `config.js` | `OOP.config.pages` (navigation order), `OOP.config.site` (masthead/footer text) |
| `storage.js` | `OOP.store.get / set / remove / getJSON / setJSON` — never throws, falls back to memory |
| `theme.js` | `toggle()`, `sync()`; global `toggleTheme()` kept from the original site |
| `layout.js` | `render()`, `setDrawer(open)`, `currentPage()`; helpers `OOP.dom.el()`, `OOP.dom.icon()`, `OOP.ui.toast()` |
| `progress.js` | `isDone / setDone / toggle`, `isLabDone / toggleLab`, `percent()`, `reset()`, `ring()`, `init()` |
| `library.js` | `visit()`, `last()`, `recent()`, `bookmarks()`, `toggleBookmark()`, `isBookmarked()` |
| `page-features.js` | `tagResourceKinds`, `addPageActions`, `addLabToggles`, `renderDashboard`, `addPager`, `addLinksFilter` |
| `search.js` | `open()`, `close()`; internals `loadIndex`, `score`, `run`, `highlight`, `go`, `jumpTo` |
| `code-viewer.js` | `hlCpp(code)`, `ct(id, line)`, `copyCode()`; wiring for tabs, wrap, full screen, bookmarks |
| `app.js` | `start()`, `bindShortcuts()`, `setReading()`, `showShortcuts()` |

### Features

- **Navigation**: grouped sidebar (desktop) / accessible drawer (mobile), breadcrumb, previous/next links, skip link, back-to-top.
- **Search** (`Ctrl/⌘ + K` or `/`): topics, headings, text, resources, lab and exam names, code file names and individual code lines. Keyboard navigable, highlights matches, jumps to the exact element.
- **Progress** (optional, local only): mark topics and individual labs complete/incomplete, overall percentage, confirmed reset. Nothing is ever marked automatically.
- **Continue learning, recently visited, bookmarks** on the Home dashboard.
- **Code viewer**: line numbers, syntax highlighting, accessible tabs, copy with confirmation, wrap toggle, full screen, click a line to highlight it, deep links like `code-files.html#sep:12`. It is a viewer — it does **not** run code.
- **All Links**: live filter that only hides rows while typing; clearing it shows everything.
- **Themes**: light/dark (saved; follows the OS until you choose). **Reading mode** (`R`). **Shortcuts help** (`?`).
- **Accessibility**: semantic headings, labelled controls, visible focus, focus-managed native `<dialog>`s, `aria-current`/`aria-pressed`/`aria-live` status, reduced-motion support, touch targets ≥ 44px on touch devices.

### Analytics (Google tag) and consent

Every page's `<head>` contains the Google tag (`G-4JHKFQBZ63`). It is preceded by `consent-init.js`, which sets Google Consent Mode to **denied** until a visitor clicks **Accept** in the small notice bar (`consent.js`). The choice is saved in `localStorage` (`oop-consent`) and can be changed any time from **Cookie settings** in the footer. The bar never blocks the page. To remove analytics entirely, delete the "Consent defaults" and "Google tag" blocks from each page's `<head>` and the `consent.js` include.

### Run locally

```bash
python3 -m http.server 8000      # or: npm run serve
# open http://localhost:8000
```

The pages also work when opened straight from disk (`index.html`), because scripts are classic (non-module) files.

### After editing content

1. Edit the relevant `.html` file (or `assets/js/code-data.js` for code).
2. Regenerate search data: `python3 tools/build_search_index.py` (or `npm run build:search`).
3. Re-run the content check (below).

To add a page: create the HTML file (copy an existing one), add an entry to `OOP.config.pages` in `config.js`, add it to `PAGES` in `tools/build_search_index.py`, and regenerate the index.

### Verify that no content changed

```bash
npm install                       # once (installs Playwright)
npm run verify                    # compares against the original single-page site (git rev 9e0769a)
```

It loads the original site and the current pages in a real browser and compares every text node, every link (exact URL) and every C++ file (SHA-256). It exits non-zero if anything differs and writes `docs/PRESERVATION-REPORT.md`. Script-added UI is tagged `data-ui` and excluded.

### Deploy to GitHub Pages

1. Push the branch to GitHub and merge it into `main` when you are happy with it.
2. Repository → **Settings → Pages** → *Build and deployment*: **Deploy from a branch**, branch `main`, folder `/ (root)`.
3. The site appears at `https://<user>.github.io/object_oriented_programming/`. All paths are relative, so no configuration is needed.

### Known limitations

- Tested automatically in Chromium only; Safari, Firefox and Edge are expected to work (standard APIs, native `<dialog>`) but have **not** been verified.
- Fonts load from Google Fonts; offline, the system fonts are used instead.
- Progress, bookmarks and "continue learning" are stored in the browser (`localStorage`) — they are per device and are lost if site data is cleared.
- Search results for code match source text, not meaning; the index must be regenerated after content edits.
