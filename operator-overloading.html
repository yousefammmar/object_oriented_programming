Key Concepts

  • Redefine operators for your own classes
  • Arithmetic operators as const members
  • Compound assignment returns *this
  • Prefix vs postfix (the int parameter)
  • << and >> as friend functions
  • Member vs friend overloading
This page is a short summary. The full notes are in Operator overloading.pdf on Google Drive.

Summary

01 · What & why

  • Redefines operators (+, -, ==, ++, << …) for your own classes, so objects behave like built-in types.
  • Write p1 + p2 instead of p1.add(p2) — cleaner code that reads like maths.

02 · Arithmetic operators

  • As a member function: Point operator+(const Point& p) const { return Point(x + p.x, y + p.y); }
  • const guarantees the current object isn't modified. -, * and / work the same way.

03 · Compound assignment

  • Point& operator+=(const Point& p) changes the current object and ends with return *this;
  • Returning *this allows chaining, and no temporary object is created.

04 · Comparison

  • bool operator==(const Point& p) const — equal when both x and y match; != works the same way.
  • bool operator<(const Point& p) const — in the notes, smaller only when both coordinates are smaller; same idea for >, <= and >=.

05 · Increment & decrement

  • Prefix Point& operator++() increments first, then returns *this — no temporary needed.
  • Postfix Point operator++(int) saves Point temp = *this;, increments, and returns the old value. The unused int is what tells them apart.
  • Decrement (--) follows the same pattern.

06 · Stream operators

  • friend ostream& operator<<(ostream& out, const Point& p); ends with return out; and enables cout << p1;
  • friend istream& operator>>(istream& in, Point& p); reads in >> p.x >> p.y; for cin >> p1;
  • They must be friends because the left operand (cout / cin) is not a Point.

07 · Member vs friend

  • Member function: the left operand must be an object of the class.
  • Friend (non-member): when the left operand isn't — e.g. cout << obj.
  • Don't overload the same operator as both — the compiler can't tell which one to call.

Extra Notes · beyond the PDF

Rules

  • You can't invent new operators or change precedence, associativity or the number of operands.
  • These can't be overloaded: ::, ., .*, ?: and sizeof.
  • At least one operand must be a class type — you can't redefine int + int.

Member or friend?

  • =, [], () and -> must be member functions.
  • If the left operand isn't your class (cout << p, 2 * p), it must be a non-member, usually a friend.
  • As a member, the left operand is *this and the right one is the parameter.

Good practice

  • Return a new object from +, - and *; return *this by reference from +=, = and prefix ++.
  • Mark operators that don't change the object as const.
  • Write != using == (return !(*this == p);) so they can never disagree.
  • Keep the meaning natural — + should add, not print.
