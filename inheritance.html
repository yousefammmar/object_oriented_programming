Key Concepts

  • Base and derived classes (is-a)
  • Single, multiple and multilevel
  • protected: the class plus its children
  • Constructors run base → derived
  • Destructors run derived → base
  • Overriding and Base::function()
  • Multiple-inheritance ambiguity
This page is a short summary. The full notes are in Inheritance.pdf on Google Drive.

Summary

01 · What is inheritance?

  • Software reuse: a derived (child) class absorbs a base (parent) class's data members and functions, then adds its own.
  • It models IS-A — every Student is also a Person. HAS-A (a Car has an Engine) is composition, not inheritance.
  • Single (Dog → Animal), multiple (SmartBoat → Boat, ComputerSystem) and multilevel (BabyDog → Dog → Animal).
  • Syntax: class Student : public Person { … };

02 · Access control

  • Private: only the class. Protected: the class and its derived classes. Public: everyone.
  • Base private members are never directly accessible in a derived class — go through public/protected setters and getters.
  • Public inheritance keeps public and protected as they are; protected inheritance makes both protected; private inheritance makes both private.

03 · Constructors & destructors

  • Neither is inherited.
  • Constructors run base → derived. Call a parameterised base constructor in the initialiser list: Student() : Person("Ali") { }
  • If you don't, the base default constructor is called — a compile error if the base only has parameterised ones.
  • Destructors run the other way: ~Derived first, then ~Base.

04 · Function overriding

  • A derived class can provide its own version of a base function: s.print() then calls Student::print().
  • Functions it doesn't redefine are inherited and used as they are.
  • Call the base version from inside the override with Person::print();

05 · Multiple inheritance

  • class Student : public Person, public Citizen { … }; inherits the members of both.
  • If both bases have a print(), s.print(); is an ambiguity error.
  • Fix it with s.Person::print();, by overriding print() in Student, with using Citizen::print;, or by renaming the base functions.

Extra Notes · beyond the PDF

Good to know

  • Not inherited: constructors, the destructor, the assignment operator and friend functions.
  • A derived object contains a full base-class part — that's why the base constructor must run first.
  • protected members are usable in derived classes but still hidden from main.

Common mistakes

  • Not calling a parameterised base constructor when the base has no default constructor — compile error.
  • Initialising base members in the derived initialiser list (Student() : name_("Ali")) — call the base constructor instead.
  • Using inheritance for HAS-A relationships — that's composition.
  • Redefining a function with a different parameter list hides every base version with that name.

Exam tip: tracing output

  • Constructors run base → member objects → derived constructor body.
  • Destructors run in exactly the reverse order.
  • Objects are destroyed in reverse order of creation, so the last object created is destroyed first.
